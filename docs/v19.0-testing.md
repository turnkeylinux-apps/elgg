# Elgg 19.0 testing

## Source decision

Debian 13 Trixie does not package Elgg. The appliance installs supported Elgg
7.0.5 from the official complete release artifact on PHP 8.4. The build checks
the upstream-published SHA-256 digest
`a369a5b97c22e31998d7ed3e107c410efbcd1d8f3a3edacea4b64af8a3027c10`.
PHP, MariaDB, Apache and required extensions come from signed Trixie
repositories.

Elgg publishes maintained complete releases through GitHub with a Composer
project and lock file. Updates are administrator-supervised replacements of
the complete application tree followed by Elgg's database upgrade command, as
documented in the README and upstream upgrade guide. The replacement retains
the database, data directory, settings, and reviewed site customizations.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance elgg \
    --source /home/agent/.local/worktrees/turnkey-apps/elgg/wish-elgg-v19-trixie
```

The command builds the Trixie root filesystem, imports it into Docker, boots
the normal systemd and firstboot path, then runs `tests/v19.sh`.

## README crosswalk

| README contract | Focused check | Required result |
| --- | --- | --- |
| Elgg provides social publishing features | Log in and create a published blog post through the real web actions, then fetch its independent view | The post title and body are returned from the persisted URL |
| Firstboot sets the administrator password, email and domain | Use the preseeded password in the CSRF-protected login action, then inspect the administrator record | Login succeeds and Elgg stores a supported password hash |
| Elgg is served over TLS | Validate Apache configuration and request application pages over HTTPS | Apache is active and Elgg pages load over TLS |
| Elgg 7.0.5 is installed from maintained upstream source | Read Composer's installed package metadata and query the official selected release tag | The runtime reports 7.0.5 and its official asset name and published SHA-256 digest match the build inputs |
| Elgg scheduled jobs execute through its CLI | Run the installed cron wrapper used by `/etc/cron.d/elgg` | The scheduled command exits successfully |
| Adminer, Webmin and local mail support are available | Query MariaDB, inspect Webmin modules and HTTPS, and check Postfix's loopback listener | The database works, Webmin answers and local SMTP listens |
| Debian packages receive Trixie updates | Inspect installed packages and active APT suites | Required PHP and MariaDB packages are installed and no Bookworm source remains |
| SSH, backup and other base services are inherited from Core | Reuse the passing Core 19 baseline | Core 19 acceptance remains the inherited evidence |

## Cheap platform preflight

`tests/v19-preflight.sh` installs the required Debian packages in a disposable
Trixie container, verifies the official complete release, runs the real CLI
installer against MariaDB, and checks the resulting version and schema. It is
a fast compatibility check before the full appliance run.

## Deferred issues

The focused test does not exercise external mail delivery or large media
uploads. It validates the normal local Postfix dependency and a representative
authenticated publishing workflow; external delivery and storage scale are
environment-specific follow-up tests.
